The main point of normal middleware comes down to three things: **Code Reusability**, **Separation of Concerns**, and the **DRY (Don't Repeat Yourself) principle**.

Without middleware, every single route handler would have to manually handle repetitive tasks like checking if a user is logged in, parsing incoming JSON data, validating input, or logging requests. Middleware lets you extract these tasks into reusable "plug-and-play" blocks that run *before* your route logic ever touches the request.

---

### Real-World Example: User Authentication & Authorization

Imagine you are building a web app. You have some public routes (`/` and `/login`) and some private routes (`/dashboard`, `/settings`, `/admin`) that only logged-in users should see.

Instead of writing verification code inside every single private route, you write a **normal authentication middleware** once and apply it only where needed.

#### 1. The Middleware (`authMiddleware.js`)

```javascript
const jwt = require('jsonwebtoken');

const requireAuth = (req, res, next) => {
  // Check if the client sent an authorization token in the headers
  const authHeader = req.headers.authorization;
  
  if (!authHeader || !authHeader.startsWith('Bearer ')) {
    return res.status(401).json({ error: 'Access denied. No token provided.' });
  }

  const token = authHeader.split(' ')[1];

  try {
    // Verify the token
    const decodedPayload = jwt.verify(token, process.env.JWT_SECRET);
    
    // Attach user info to the request object so downstream routes can use it
    req.user = decodedPayload;
    
    // Everything is good! Pass control to the next function (the actual route)
    next();
  } catch (err) {
    return res.status(403).json({ error: 'Invalid or expired token.' });
  }
};

module.exports = requireAuth;

```

#### 2. Using It in Your Routes (`server.js`)

```javascript
const express = require('express');
const app = express();
const requireAuth = require('./authMiddleware');

// Public route - anyone can access it
app.get('/', (req, res) => {
  res.send('Welcome to the home page!');
});

// Protected route - 'requireAuth' runs FIRST. 
// If it fails, it sends a 401 response and stops. 
// If it succeeds, it calls next() and lets the user view the dashboard.
app.get('/dashboard', requireAuth, (req, res) => {
  res.json({ message: `Welcome back, user ID: ${req.user.id}!` });
});

// Another protected route sharing the exact same security logic
app.get('/settings', requireAuth, (req, res) => {
  res.json({ settings: 'Here are your account settings...' });
});

```

### Other Common Real-World Uses for Normal Middleware

You actually use normal middleware all the time without realizing it because Express comes with built-in ones or popular third-party ones:

* **`express.json()`:** A built-in middleware that intercepts incoming requests, parses raw JSON data from the body, and attaches it to `req.body`. Without it, `req.body` would be `undefined`.
* **CORS (`cors` package):** Middleware that automatically adds headers to your response allowing your frontend (running on a different port or domain) to talk to your backend API.
* **Request Loggers (`morgan` package):** Middleware that automatically logs every incoming request method, URL, and response time to your console for debugging.
